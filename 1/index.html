Images of the Russian Empire: Colorizing the Prokudin-Gorskii photo collection

Overview

In 1907, a man named Sergei Mikhailovich Prokudin-Gorskii traveled around Russia to take photographs of empirial Russia. However, instead of capturing black and white images, he took three images at different exposures using red, blue, and green filters. Thankfully, the Library of Congress has purchased the RGB negatives and they are available to be downloaded online. The task of this project is to use various alignment techniques as well as post-processing steps to accurately line up the RGB images.

Part 1: Aligning Small-Scale Images

I first started off with implementing the euclidean norm (L2 norm). First, I only looked at the top left corner of the image, but later I modified the function to also make the window dynamic (smaller and/or shifted).

Naive alignment algorithm overview

For the alignment algorithm, I looped through a window of [-15,15] for both x and y coordinates. For every new point in the window, I shifted the non-blue channel using np.roll, such that the top leftmost corner of the channel was at the chosen point. I then called on my metrics (euclidean or ncc) function to obtain a scalar value and updated my best metric and best coordinate values in accordance with the scalar metric output. The algorithm returned both the aligned non-blue channel and the coordinates by which the channel was shifted.

Euclidean norm overview

As outlined on the course website, I used the following equation: sqrt(sum(sum((image1-image2).^2))), which I then incorporated into a "naive_align" function.

Normalized cross correlation (ncc) overview

I first converted my image vectors from 2D to 1D, then followed the equations from the course website: (image1./||image1|| and image2./||image2||) to obtain a single scalar value. I had to work with the images as 1D vectors to obtain a single scalar metric output.

For the following images, I only used euclidean norm/ncc, no pyramid and no bells and whistles.

Part 2: Multi-scale Pyramid Alignment

I found the MIT Computer Vision textbook helpful when implementing my Gaussian pyramid. Out of all of the project algorithms, I struggled with this one the most (because I forgot what recursion was).

First, I changed my naive alignment implementation to handle a dynamic window. When recursing to the maximum pyramid depth, the smallest image will look at the top leftmost corner of some predefined size (I chose to look at height//10, width//10) and choose the best coordinates from that corner. Every subsequent upward step in the pyramid will use that best coordinate and construct a new window based on the coordinates found in the previous step. A small point I had to debug was how much the window should decrease from step to step. I decided to first use a static offset to adjust window size, but then realized the offset should change based on pyramid level to make the process more efficient.

Part 3: Bells & Whistles

Automatic cropping surprisingly took up most of my time and I was very frustrated with it. I initially thought about using edge detection (even before we had the lecture on it) but I also had to think long and hard about how to find the image borders. Phase alignment was easier to implement than I thought it would be and the results were striking. I'm still not sure why some images (like the monastery) refuse to be aligned even after using Fourier Transforms.

Note: I implemented the bells and whistles in the order they are presented.

Automatic Cropping

First, I used an edge detection algorithm to outline the edges in the image. I used skimage's Canny filter because it seemed to have more control over thresholding, but ended up performing about the same as the Sobel filter. Next, I summed the image along the x and y axes and looped through the first tenth of the rows and columns in the image, keeping track of the maximum value and assigning the vertical and horizontal border to argmax. Since a border is a vertical or horizontal line, the maximum value in the appropriate part of the image should correspond to an edge! For the right and bottom borders, I looped through the last tenth of the rows and columns of the image (right to left) to detect the argmax.

Coordinates for cropping for all channels in the Emir image ended up being:

  • Top left corner is (319, 369)
  • Bottom right corner is (2890, 3333)

Problems

The main issue is that the borders are not perfect horizontal and vertical lines, so this approach won't work if there are a lot of edges right next to the border of the image. (for example: the melons image, where the algorithm cropped too much). For this approach, more sophisticated algorithms should be explored (or I guess slap an ML model on it, as most people do nowadays).

Better feature mapping: Phase Alignment

Here, I followed the Wikipedia article on phase correlation. To compute our phase correlation, we take the Fourier transform of our two image channels and compute their cross-power spectrum, which returns a peak where the images are most aligned in Fourier space. Then, we take the inverse Fourier transform to find the correlation peak back in our original image land and find the image coordinates corresponding to that peak. The results of the algorithm are stunning.

Melons: R (14, 176), G (8, 79)
Harvesters: R (11, 118), G (11, 55)
Self-Portrait: R (37, 175), G (29, 77)

Automatic White Balancing

I referenced the following Wikipedia article for color balancing and followed this equation: 255/(max value of the channel) for each of the RGB channels and then multiplied each channel by the resulting scalar value. However, the results are very underwhelming because the maximum values at each channel were already close to 255 so there wasn't much white-balancing that occurred.

Adjusting Contrasting

Histogram Equalization

I wanted to implement it myself, but I didn't have enough time, so instead I used skimage's exposure.equalize_hist and exposure.equalize_adapthist. Equalize histogram works just as described in lecture, where we flatten the histogram of the image to increase contrast. And as opposed to the global contrast enhancement in regular histogram equalization, adaptive histogram equalization does contrast enhancement over local tiles of the image, as described in the function description.

Power Law Transformations

Here, I again used skimage's functions for adjusting image exposure: gamma, log, and sigmoid. These functions use the power-law transforms we learned in class, where the normalized pixel intensity (range must be 0-1) is raised to the power of the gamma, log, etc to increase contrast.
